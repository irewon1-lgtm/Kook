# KR4 재무자료 검증 및 기존 판정 기준

기준 코드는 기존 `scripts/collect_financial_safety.py`의 `STAGE4_BS_SAFETY_V1`이다. 임계값과 판정 순서는 변경하지 않는다. 이 상태는 종목 공개·M01~M04 계산·점수·조합별 순위를 변경하지 않는다.

- 자료 확인(PASS): 다섯 필수 항목이 있고 자산총계가 양수이며, 자산=부채+자본 오차가 자산 대비5% 이내이고, 자본총계>0, 부채/자본≤400%, 유동자산/유동부채≥70%를 모두 만족한다.
- 재무위험(FAIL, 빨강): 필요한 자료와 회계 일치 검증 후 자본총계≤0, 부채비율>400%, 유동비율<70% 중 기존 판정 순서상 해당하는 조건이 실제 수치로 확인된다.
- 미확보(HOLD, 주황): 원자료·필수 항목·단위·기간·법인 매핑·최종 공시·정정 수치 일치 중 검증되지 않은 부분이 있거나, 기존 회계 오차/분모 조건을 통과하지 못한다. 결측은0으로 대체하지 않는다. 실제0은0으로 보존하며 유동부채0은 무한대의 정상 비율로 만들지 않는다.
- 비교제외(NOT_APPLICABLE): 기존 금융·보험·은행·증권·신탁·여신 업종 구분을 유지한다. 실제 확보한 원자료는 보여주되 일반기업 비율로 위험을 판정하지 않는다.

공식 OpenDART 최근4개 재무상태표 ZIP에서 종목별 실제 최신 보고기간을 고르고, 하나의 연결/별도 재무 범위·기간·통화 안에서만 항목을 취한다. 단위 변환이나 환율 추정은 하지 않는다. 동일 우선순위의 계정 값이 충돌하거나 회사명/기간이 섞인 자료는 보류한다. 원본 정수는 Android에서도 Long으로 보존한다.

공식 OpenDART 기업 목록의 종목코드·법인코드와 최종보고서 목록의 실제 공시일·보고기간·접수번호를 대조한다. Actions Secret `OPENDART_API_KEY`가 있으면 공식 인증 API를 사용하며, 키가 없는 환경은 공개 DART 최종보고서 조회를 사용한다. 키는 요청 인증에만 쓰고 증거 URL·캐시·로그·APK에 저장하지 않는다.

정정공시의 존재만으로 ZIP 수치가 그 정정을 포함한다고 가정하지 않는다. 인증 API `fnlttSinglAcntAll`의 실제 재무상태표 행에서 법인·접수번호·사업연도·보고서·연결/별도·통화와 다섯 필수 항목을 대조한다. 다섯 원본 정수 모두 정확히 일치할 때만 기존 ZIP 값을 그대로 검증하며, API 수치로 대체하거나 누락을 채우지 않는다. 명시적 오류·금액/접수번호 불일치·복수 관측은 검증 증빙으로 사용할 수 없다. 정정 원문 금액을 대조하지 못한 종목은 `CORRECTION_VALUES_NOT_RECONCILED`로 보류하고 구체적인 대조 실패 사유도 표시한다.

독립 게시 파일은 `evidence/financial_safety_snapshot.json`이다. M01~M04 파일을 수정하거나 재무 수집 성공을 그 갱신의 전제조건으로 삼지 않는다. Android는 기준일·전체 종목 식별 집합·기존 정책·원시 금액과 비율·공시 근거를 따로 검증한다. 날짜 불일치나 검증 실패는 Stage4와 의존 후보만 보류하고 정상4지표 수신·순위 공개를 유지한다.

각 상태 표시를 누르면 실제 금액, 통화, 보고기간, 실제 공시일, 연결/별도, 법인/접수번호, 판정·보류 사유, 공식 공시 URL 및 OpenDART ZIP/해시를 확인할 수 있다. 검증되지 않은 원문 금액은 ‘검증 대기’로 구분한다. 구버전 캐시에서 원문 증빙을 확보하지 못한 경우 그 금액을 추정하지 않는다.

수동 실행(`workflow_dispatch`), 예약 실행(`schedule`), 4지표 수집 후 실행(`workflow_run`)은 실제 GitHub 이벤트별로 구분한다. 일시적 통신 오류는 속도 제한·최대3회·원본 해시 검증을 유지하며 재시도하고, 출처 장애가 남으면 수집 검증을 실패 처리한다. 오류가 있어도4지표 갱신은 독립적으로 실행된다.
